Compatible transitive updates were resolved into the lockfile, and third-party
notices were regenerated. Other direct dependencies already use their latest
stable versions, with two compatibility exceptions:

- React stays at **19.3.0**, the exact version specified by the current Expo SDK
  and used by React Native 0.88's renderer. The npm latest tag is 19.3.1.
- TypeScript stays at **6.0.3**. The latest stable `typescript-eslint` supports
  `>=4.8.4 <6.1.0`, so TypeScript 7.0.2 is outside its supported range.
  [Parser compatibility policy](https://typescript-eslint.io/users/dependency-versions/)

Expo SDK 58 remains the latest stable SDK. Its
[upgrade guidance](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/)
requires aligning dependencies with the SDK. No unsupported peer-dependency
override was introduced.

`react-native-tcp-socket` remains pinned to its
[latest stable release, 6.4.3](https://github.com/Rapsssito/react-native-tcp-socket/releases/tag/v6.4.3).
Helyon's Android patch still applies and remains necessary for network-scoped
DNS, IPv6 binding, USB selection and failed-connect cleanup.

## Upstream audit findings

`npm audit` still reports **five high-severity package findings** in the Expo CLI
dependency chain. They trace to two advisories:

- [node-forge signature verification](https://github.com/advisories/GHSA-86w9-cpqp-85rv):
  the latest release, 1.4.0, is affected and no patched version is listed.
- [Zod collection validation](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5):
  Expo's CLI requires Zod 3.25.76 through its v3 constraint. The advisory lists
  4.6.6 as patched; the installed v4 copy used elsewhere is already 4.6.7.

The audit's suggested Expo downgrade was not applied. Neither node-forge nor
Zod code appears in the exported app source maps. Expo's Metro require loader
does appear, so this is a check of the affected modules rather than a claim
that no CLI-sourced code is bundled.
